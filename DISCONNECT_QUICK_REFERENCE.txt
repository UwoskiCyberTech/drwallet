================================================================================

STEP 1: Click the Red "✕ Disconnect" Button
  Location: Top right of header
  Color: Bright red
  Label: "✕ Disconnect"
  Action: Immediately disconnects wallet

STEP 2: Button Changes
  Before: [✕ Disconnect] button visible
  After:  [✕ Disconnect] button disappears
          [Connect Wallet] button reappears

STEP 3: Reconnect to Test Again
  Action: Click "Connect Wallet"
  Result: Fresh connection triggers new charge
          Telegram notified again

================================================================================
WHAT HAPPENS WHEN YOU CLICK DISCONNECT
================================================================================

Immediate:
  1. Button click is registered
  2. Wallet disconnects instantly
  3. "✕ Disconnect" button vanishes
  4. "Connect Wallet" button appears

In Your Wallet (MetaMask):
  - Still shows the site is connected
  - But app treats you as disconnected
  - You can see in MetaMask settings
  - To fully disconnect in MetaMask:
    Click MetaMask → Click three dots → "Disconnect this site"

In the App:
  - Address removed from header
  - Balance display cleared
  - Network selector hidden
  - All wallet-dependent features disabled

================================================================================
TROUBLESHOOTING
================================================================================

Problem: Can't find the red disconnect button
Solution 1: Refresh page (F5)
Solution 2: Scroll right if on small screen
Solution 3: Rebuild app (npm run dev after Ctrl+C)

Problem: Button is there but doesn't work
Solution 1: Try clicking again
Solution 2: Hard refresh (Ctrl+F5)
Solution 3: Restart npm run dev

Problem: After disconnect, can't reconnect
Solution 1: Refresh page
Solution 2: Clear browser cache (Ctrl+Shift+Del)
Solution 3: Close and reopen app

Problem: Charge doesn't trigger after reconnect
Solution 1: Check balance is sufficient
Solution 2: Verify network is supported (all EVM chains are)
Solution 3: Check .env.local credentials
